# Отчёт: браузерный агент на локальной LLM, этапы 1–7

Chrome-расширение (Manifest V3, WXT + TypeScript + Preact). Локальная LLM на сервере в локальной сети управляет браузером: читает страницу, кликает, вводит текст, прокручивает и переходит по ссылкам, пока не выполнит задачу.

Состояние на 19.10.2026: все 7 этапов готовы, **384 юнит-теста проходят**, сборка лежит в `dist/chrome-mv3`. Установка и настройка сервера — в [README.md](README.md).

## Как устроен агент

Один шаг цикла:

1. **Смотрит (расширение).** Content script обходит страницу и все её фреймы. Видимые интерактивные элементы получают номера, и всё превращается в компактный текст: `[27] button "Пора поверстать"`, плюс адрес, прокрутка и видимый текст страницы с номерами на местах элементов.
2. **Решает (модель).** Текст уходит на сервер вместе с задачей, историей и системным промптом. Модель отвечает JSON: `{"reasoning", "expected_outcome", "actions":[{"action":"click","index":27}]}`.
3. **Делает (расширение).** По номеру находит элемент и кликает или вводит текст настоящими событиями через CDP. Если CDP недоступен — DOM-событиями.
4. **Повторяет** до `done` или `ask_user`, с лимитами и детектором зацикливания.

Модель **не видит картинку страницы**: всё восприятие текстовое. Поэтому качество агента почти целиком зависит от сборщика — большая часть доработок касалась именно его.

## Окружение и решения до старта

- Node.js не было — установлен через Homebrew (Node 26).
- Проект перенесён из папки Google Drive в `~/dev/llm_chrome`, чтобы `node_modules` не синхронизировались. Старая папка в Drive не тронута, она пустая.
- Сборка вынесена из скрытой `.output/` в видимую `dist/` (`outDir: 'dist'`).

**Замечания к ТЗ, согласованные до реализации:**

| # | Замечание | Решение |
|---|---|---|
| 1 | Стрима мало, чтобы service worker не выгружался: таймер простоя сбрасывают только вызовы extension API | «Пульс» — `getPlatformInfo()` каждые 20 с на всё время запуска |
| 2 | Ollama через `/v1` не принимает `num_ctx` и молча обрезает промпт | Проверка связи показывает реальный контекст сервера и предупреждает о расхождении |
| 3 | Грамматика JSON может ломать рассуждения thinking-моделей | Режим structured output настраивается: `auto / json_schema / json_object / off` |
| 4 | Ночная 32B отвечает минутами | Несколько действий за шаг (`actions[]`, до 4) |
| 5 | Флагу риска от модели нельзя доверять при инъекции | Флаг только повышает уровень подтверждения (это этап 6) |
| 6 | Два режима работы | Профили «Быстрый» и «Ночной» |
| 7 | Агенту нужен доступ к любым страницам | `host_permissions: <all_urls>`; это же разрешение покрывает запросы к серверу |
| 8 | Рассуждения Qwen3 тратят время | Переключатель «Рассуждения» в профиле: быстрый — выкл, ночной — вкл |

## Этап 1 — каркас, настройки, проверка связи

- **Каркас WXT:** `background`, side panel, страница настроек (открывается при установке), manifest с разрешениями `storage`, `sidePanel`, `scripting`, `debugger` и `<all_urls>`.
- **Настройки** ([src/lib/settings.ts](src/lib/settings.ts)):
  - два LLM-профиля, у каждого свои адрес, ключ, модель, температура, бюджет контекста, лимит токенов, таймаут и режим structured output;
  - позже добавлены переключатель рассуждений и «Доп. параметры запроса» (JSON, подмешивается в тело запроса);
  - любые сохранённые данные приводятся к корректному виду: недостающее берётся из дефолтов, числа зажимаются в диапазоны;
  - хранение в `storage.local`, чтобы API-ключ не уходил в облачную синхронизацию.
- **Проверка связи** ([src/lib/llm/connection.ts](src/lib/llm/connection.ts)):
  - `/v1/models`;
  - тип сервера: Ollama через `/api/version` и `/api/ps`, llama.cpp через `/props`;
  - реальный контекст сервера;
  - понятные подсказки на ошибки 401/403/404, таймаут и недоступную сеть.
- **Пробная генерация со стримом:** время до первого токена и отдельный счёт рассуждений (`reasoning_content` у llama.cpp, `reasoning` у Ollama).
- **Проверено вами** на llama-server `192.168.0.3:8080` с моделью qwen3:14b: первый токен за 113 мс, ответ «OK».

## Этап 2 — восприятие страницы

- **Сборщик** ([src/lib/dom/collect.ts](src/lib/dom/collect.ts)) находит:
  - `button`, `a[href]`, поля ввода, `select`, `[role=…]`, `contenteditable`, `onclick`, `tabindex>=0`;
  - элементы с `cursor:pointer` — единственный внешний признак кликабельности в SPA.

  Учитывает открытые shadow root и iframe того же origin. Видимость проверяется через `checkVisibility`. Перекрытие модалками — через `elementFromPoint`, кто на самом деле получит клик. Слайды карусели за краем экрана отбрасываются. Пароли и номера карт модели не показываются (`•••`).
- **Сериализатор** ([src/lib/dom/serialize.ts](src/lib/dom/serialize.ts)):
  - формат из ТЗ: `[13] input[type=email] placeholder="Email" value=""`;
  - зоны «выше экрана / на экране / ниже экрана»;
  - **никогда не превышает лимит символов**: сначала элементы на экране, затем ближние ниже, затем выше;
  - под текст страницы гарантирует до 20% лимита;
  - сколько элементов не влезло, пишет прямо в текст.
- **Debug-подсветка** ([src/lib/dom/overlay.ts](src/lib/dom/overlay.ts)): рамки с номерами в изолированном shadow root, клики не перехватывает, следует за прокруткой.
- **Content script внедряется по требованию** (`chrome.scripting`), поэтому работает и во вкладках, открытых до установки расширения.
- **В side panel** блок «Что видит модель»: показать, копировать, подсветка.
- **Инструмент «Почему не виден?»** ([src/lib/dom/diagnose.ts](src/lib/dom/diagnose.ts), [picker.ts](src/lib/dom/picker.ts)), добавлен по ходу:
  - кликаете элемент на странице, и панель объясняет, какое правило его отбросило: перекрыт, невидим, не влез в лимит, скрыт заметкой, не распознан;
  - работает по журналу решений сборщика.

## Этап 3 — LLM-клиент и один шаг вручную

- **Клиент** ([src/lib/llm/client.ts](src/lib/llm/client.ts)):
  - стриминг SSE через свой инкрементальный парсер ([sse.ts](src/lib/llm/sse.ts)), устойчивый к разрезам посреди строки и UTF-8 символа;
  - в режиме `auto` пробует `json_schema`, при отказе сервера — `json_object`, затем без формата, и запоминает, что сработало;
  - выключение рассуждений отправляет `chat_template_kwargs.enable_thinking=false` (llama.cpp) и `think=false` (Ollama).
- **Схема действий** ([src/lib/agent/actions.ts](src/lib/agent/actions.ts)): 12 действий из ТЗ, JSON Schema собрана только из конструкций, которые понимает конвертер грамматик llama.cpp.
- **Парсер ответа** ([src/lib/agent/parse.ts](src/lib/agent/parse.ts)):
  - вырезает рассуждения (`<think>`, незакрытые блоки, формат gpt-oss), markdown и текст вокруг JSON, чинит висячие запятые;
  - понимает вариации полей (`fill` вместо `type`, `"[12]"` вместо `12`, одно действие без обёртки);
  - строго проверяет смысл;
  - после `done`, `ask_user` и смены страницы отбрасывает остаток цепочки;
  - при ошибке модель переспрашивается до 2 раз с текстом ошибки.
- **Системный промпт — отдельный файл** [src/prompts/system.md](src/prompts/system.md), написан на английском:
  - содержимое страницы обёрнуто в метки со случайным идентификатором, и страница не может подделать закрывающую метку;
  - промпт прямо требует считать текст страницы данными, а не инструкциями;
  - метка постоянна в пределах задачи, а страница стоит в конце сообщения, чтобы сервер переиспользовал кэш начала промпта.
- **«Пульс»** ([src/lib/keepalive.ts](src/lib/keepalive.ts)) и оценка размера промпта относительно бюджета контекста.

## Этап 4 — полный цикл агента

- **Цикл** ([src/lib/agent/runner.ts](src/lib/agent/runner.ts)): наблюдение → модель → одобрение → выполнение.
  - Пауза вступает в силу между действиями, стоп обрывает и запрос к модели.
  - `ask_user` ждёт вашего ответа в панели и передаёт его модели.
  - `extract` сохраняет найденное, и оно всегда попадает в промпт.
  - Ограничения: лимит шагов, таймаут на действие, остановка после 3 ошибок модели подряд.
- **Детектор зацикливания** ([src/lib/agent/loop.ts](src/lib/agent/loop.ts)): одно и то же действие на неизменной странице. На 3-м повторе модель получает предупреждение в истории, на 6-м агент останавливается.
- **История** ([src/lib/agent/history.ts](src/lib/agent/history.ts)): последние 3 шага подробно, более старые — одной строкой, при нехватке места выбрасываются самые старые.
- **Исполнитель на DOM-событиях** ([src/lib/dom/act.ts](src/lib/dom/act.ts)):
  - клик полной цепочкой событий мыши;
  - ввод текста, который замечают React и Vue;
  - Enter с отправкой формы;
  - `select` по тексту или значению;
  - прокрутка нужного контейнера;
  - после действия — ожидание, пока DOM перестанет меняться.
- **Переходы и вкладки** ([src/lib/tab-actions.ts](src/lib/tab-actions.ts)): `navigate` (только http/https), «назад», новая вкладка, переключение. Если клик открыл новую вкладку, агент сам переходит работать туда.
- **Временная подстраховка до этапа 6:** галочка «Подтверждать каждый шаг» (по умолчанию включена). Перед кликами, вводом и переходами агент ждёт «Выполнить» или «Отклонить».
- **Журнал** ([src/lib/log/db.ts](src/lib/log/db.ts)): IndexedDB, последние 50 запусков, экспорт в JSON. По желанию — отправка POST на адрес из настроек ([remote.ts](src/lib/log/remote.ts)).
- **Панель:** Старт / Пауза / Стоп, статус, одобрение, вопрос модели, результат, лента шагов (новые сверху, «Что видела модель» раскрывается по запросу), журнал запусков.
- Исполнитель проверен на живой Википедии: клик раскрыл поиск, ввод «Казань» с Enter открыл статью.

## Этап 5 — CDP-исполнитель, курсор, iframe с других сайтов

- **CDP-драйвер** ([src/lib/exec/cdp.ts](src/lib/exec/cdp.ts)): события `isTrusted` через `Input.dispatchMouseEvent`, `Input.insertText` и `Input.dispatchKeyEvent`.
  - Мышь ведётся плавной траекторией с лёгким изгибом (срабатывают hover-меню), с небольшими случайными паузами.
  - Cmd/Ctrl+A с командой `selectAll`, Enter, Backspace.
  - Учитывается масштаб страницы.
- **Сессии отладчика** ([src/lib/exec/debugger.ts](src/lib/exec/debugger.ts)): подключение при первом клике, отключение в конце запуска. Если вы закрыли плашку Chrome, агент переходит на DOM-события, и в результате шага появляется пометка об этом.
- **Точка клика** (`findClickPoint`): элемент прокручивается в центр экрана, затем ищется точка внутри него, где он сам верхний (центр, потом четверти). Так клик не уходит в липкую шапку или всплывашку.
- **Ввод через CDP:** настоящий клик (фокус), «выделить всё», вставка текста. Затем проверка, что текст действительно оказался в поле.
- **Визуальный курсор** ([src/lib/dom/cursor.ts](src/lib/dom/cursor.ts)): стрелка плавно едет к точке и показывает «нажатие». Чистая косметика, клики не перехватывает.
- **iframe с других сайтов** ([src/lib/frames.ts](src/lib/frames.ts), [src/lib/perception.ts](src/lib/perception.ts)):
  - скрипт внедряется во все фреймы;
  - родитель метит свои `iframe` токенами через `postMessage`, фреймы сообщают токен, и из этого строится дерево фреймов с координатами;
  - каждый фрейм собирается в координатах верхней страницы, номера сквозные;
  - перед кликом координаты фрейма пересчитываются заново.

  Разрешение `webNavigation` (Chrome предупреждает о нём как о «чтении истории») не понадобилось.
- **Редакторы кода** (CodeMirror 5/6, Monaco, Ace) показываются одним полем `code-editor`, код — в тексте страницы построчно. `type` заменяет весь код в редакторе. Без CDP агент честно отказывается от ввода в такой редактор.

## Этап 6 — безопасность, автономный режим, чекпоинты

**Решения, согласованные до реализации:**
- Отложенное действие нельзя повторить утром «как есть»: `click [27]` ссылается на страницу, которой уже нет. Поэтому утром «Продолжить отсюда» запускает обычный запуск с той страницы и контекстом ночной задачи.
- По сайтам: «спрашивать / выполнять без подтверждения / запрещать», плюс список кнопок-исключений.
- Звуковой сигнал, когда ночью агент упирается в рискованное действие.
- `ask_user` ночью: модель решает сама.
- Продолжение после перезапуска: ночью само, днём — по кнопке.

- **Оценка риска** ([src/lib/agent/risk.ts](src/lib/agent/risk.ts)). Решение принимает расширение, а не модель:
  - **оплата** — кнопки «оплат…/купить/оформить заказ/pay/checkout…», любые действия на адресах с `checkout`, `payment`, `pay`, `billing`;
  - **удаление** — «удали…/очистить/delete/remove…»;
  - **отправка** — «отправить/опубликовать/send/post/submit…», а также Enter в `textarea` или `contenteditable` (кроме поиска);
  - **пароль/карта** — ввод в такое поле и отправка формы с ним. Исключения по тексту кнопки это правило не снимают.
  - Слово совпадает по началу слова: «удали» ловит «Удалить», но не «Удалённая работа». «pay» ловит `/pay/` и `pay.example.com`, но не `paypal` в адресе.
  - Словари правятся в настройках («Безопасность»).
  - Модель может прислать `"risky": true`. Флаг только добавляет подтверждение, снять его нельзя.
- **Метаданные элементов** ([collect.ts](src/lib/dom/collect.ts), `riskFlags`): `secret`, `submit`, `form-secret`, `search`, `message`. Модель их не видит: они идут только в `handle.flags` для классификатора.
- **Обычный режим.** Шаг с рискованным действием ждёт «Выполнить / Отклонить». Карточка красная, у каждого действия указана причина. Безопасные шаги идут без остановок.
- **«Подтверждать каждый шаг»** стал отладочным режимом и **по умолчанию выключен**. В автономном режиме не действует.
- **Автономный режим:**
  - рискованное действие → звук (offscreen-документ, Web Audio) и системное уведомление; клик по уведомлению открывает вкладку агента;
  - агент ждёт подтверждения N секунд (по умолчанию 120, в панели виден обратный отсчёт);
  - нет ответа → безопасная часть цепочки выполняется, рискованное уходит в **очередь на утро** (IndexedDB), модель получает `POSTPONED… do not retry`;
  - одно и то же действие дважды не откладывается;
  - 3 шага подряд упёрлись в отложенное → запуск завершается статусом «ждёт утра»;
  - к `done` дописывается, сколько действий ждут подтверждения;
  - `ask_user` → «пользователь спит, реши сам и укажи допущение».
- **Заметки для сайтов:** «Рискованные действия на этом сайте: спрашивать / выполнять без подтверждения / запрещать» и «Не спрашивать подтверждения для» (тексты кнопок). При запрете модель получает `BLOCKED… do not try again`.
- **Очередь на утро** (панель): задача, страница, действие с причиной, обоснование модели. Кнопки:
  - «Продолжить отсюда» — открывает страницу и начинает обычный запуск: исходная задача, отложенное действие по описанию элемента, сохранённые `extract`;
  - «Открыть страницу»;
  - «Убрать».

  Разобранные элементы старше 14 дней удаляются.
- **Чекпоинты:**
  - перед каждым действием и перед ожиданием одобрения или ответа в журнал пишутся шаг и состояние: какое действие выполняется, детектор цикла, отложенное;
  - в `storage.local` (`activeRun`) хранятся конфиг и вкладка;
  - воркер проверяет чекпоинт при запуске браузера (`runtime.onStartup` — без этой подписки Chrome сам воркер не будит), при обновлении расширения и при любом пробуждении.
- **Продолжение после перезапуска:**
  - вкладка ищется по id с тем же адресом, затем по адресу, иначе открывается заново;
  - действие, на котором прервались, помечается «may or may not have happened», невыполненные — «not executed», модель получает пометку о перезапуске;
  - одобрение по старым номерам не восстанавливается — шаг перепланируется;
  - ночью продолжает сам через 5 с (вкладки успевают восстановиться), днём в панели «Задача прервана: Продолжить / Отменить».
- Иконка расширения (нужна и для уведомлений), разрешения `offscreen` и `notifications`.

**Прогон в Chromium** (Playwright, подставной OpenAI-совместимый сервер со сценарием «впиши комментарий и оплати»):
- автономно: сигнал и окно 3 с → комментарий вписан, «Оплатить» не нажат, в очереди 1 элемент, результат «Ждут подтверждения: 1»;
- утром «Продолжить отсюда»: промпт содержит ночной контекст, подтверждение без таймера → «Выполнить» → оплачено, элемент очереди «продолжено»;
- браузер закрыт посреди ночной задачи → при запуске воркер стартовал сам, тот же запуск продолжился (`restarts=1`), модель получила пометку о перезапуске;
- то же днём → «Задача прервана», «Отменить» сохраняет запуск как остановленный;
- «Проверить сигнал» в настройках срабатывает без ошибок. Слышен ли звук на Mac, нужно проверить вам.

**«Скрыть от модели» для иконок** (доработка после этапа 6, [src/lib/dom/hide-rules.ts](src/lib/dom/hide-rules.ts)):
- Правило — текст (ищется в имени, `aria-label` и `title`, без учёта регистра) или `css: селектор` для иконок без текста.
- Скрытый элемент вырезается целиком: модель не видит ни его строки в списке, ни текста, ни вложенных элементов. Раньше текст скрытой ссылки мог остаться в тексте страницы.
- Кнопка «Скрыть элемент…» в панели «Что видит модель»:
  - кликаете элемент на странице, и правило строится для того элемента, который видит модель (кнопка, а не svg внутри);
  - у кнопки с текстом правило — текст, у иконки — самый точный стабильный селектор. Сгенерированные классы вроде `css-1a2b3c` не используются, слишком общий селектор уточняется предком;
  - показано, сколько элементов попадёт под правило; правило и сайт можно поправить и записать в заметку («Скрыть»).
- Проверено в Chromium на копии шапки и боковой панели урока: «Мои курсы», «Подарок за друга», аватар, тема, избранное, чат поддержки → модели осталась только «Дальше».

**Принудительная прокрутка при застревании** ([src/lib/agent/stuck.ts](src/lib/agent/stuck.ts)):
- Симптом на тренажёре: модель вставляла код, жала неактивную «Проверить», вставляла тот же код снова. Детектор зацикливания это пропускал, потому что шаги не одинаковые.
- Шаг считается бесполезным, если на том же месте (URL + прокрутка) действие не удалось, «ничего не изменилось» или всё уже делалось здесь же.
- После N таких шагов подряд (настройка «Застрял — прокрутить вниз…», по умолчанию 2, 0 — выкл) агент сам прокручивает на экран вниз, а модель получает `AUTO-SCROLL… do not repeat`. Если ниже некуда — `STUCK…` с советом сменить подход.
- В системный промпт добавлено: неактивная кнопка после уже сделанного — не путь вперёд, не повторяй ввод, ищи «Далее» ниже.

**Облачный провайдер (Google Gemini)** — доработка после этапа 6, [src/lib/llm/providers.ts](src/lib/llm/providers.ts):
- У профиля появилось поле «Провайдер»: «свой сервер» (как было) или «Google Gemini». Провайдер задаёт префикс пути (`/v1` против `/v1beta/openai`) и мелочи тела запроса; протокол тот же OpenAI-совместимый, отдельного клиента не понадобилось.
- Добавлен третий профиль «Облако» с Gemini, чтобы «Быстрый» и «Ночной» остались локальными. Переключение провайдера подставляет его адрес и модель, не затирая набранное руками.
- Ключ — `Authorization: Bearer`, хранится в `storage.local` (не уезжает в синхронизацию Google).
- Рассуждения у Gemini выключаются через `reasoning_effort: none` вместо `chat_template_kwargs`/`think`.
- `models/gemini-…` из списка моделей приводится к `gemini-…`, иначе проверка связи не узнавала бы модель.
- Проверка связи для облака не долбится в `/api/version` и `/props` — их там нет; тип сервера `google`.
- **Повтор без необязательных полей.** Если сервер отвечает 400 с жалобой на `stream_options`, `reasoning_effort` и т.п., клиент повторяет запрос без них и запоминает это. Работает для любого OpenAI-совместимого сервиса, не только Gemini.
- В настройках — предупреждение, что текст каждой страницы уходит на чужой сервер, и ссылка за ключом.
**Любой OpenAI-совместимый сервис по ключу** ([url.ts](src/lib/llm/url.ts)):
- Адрес теперь можно вписывать вместе с версией — `https://vyceai.com/v1`. Раньше `/v1` срезался и добавлялся обратно, так что сервис с другим префиксом (`/v2`, `/api/v1`) не подключился бы. Теперь путь из адреса сохраняется, а префикс провайдера добавляется, только если версии в адресе нет.
- Проверка связи показывает, куда реально пойдут запросы: `Соединение есть: https://vyceai.com/v1/chat/completions`.
- Внешний сервер определяется по адресу, а не по названию провайдера: `localhost`, `127.*`, `10.*`, `192.168.*`, `172.16–31.*`, `*.local`, `*.lan` и имена без точки — своя сеть, остальное — внешний.
  - Для внешнего адреса показывается предупреждение, что текст страниц уходит наружу.
  - Служебные пути Ollama (`/api/version`) и llama.cpp (`/props`) на внешний сервер не запрашиваются: это лишние обращения с вашим ключом. На свой сервер они идут от корня, даже если адрес вписан вместе с `/v1`.
- Проверено в Chromium на стороннем сервисе с ключом `sk-…`: список моделей, пробная генерация и полный шаг агента проходят, лишних путей не дёргается.

**Терпимость к перегрузке сервиса** ([client.ts](src/lib/llm/client.ts), [runner.ts](src/lib/agent/runner.ts)):
- Облако отвечает `503 This model is currently experiencing high demand`, `429` и т.п. Раньше три таких ответа подряд убивали запуск с сообщением «модель не дала годного ответа» — хотя модель вообще не отвечала.
- Временные неполадки (408, 429, 500, 502, 503, 504, 529, обрыв сети) теперь отличаются от негодного ответа модели:
  - внутри шага запрос повторяется до 3 раз с паузой 2 с и 6 с (с разбросом), `Retry-After` от сервера уважается, но не дольше минуты;
  - если и это не помогло, цикл агента ждёт 5 с, 15 с, 45 с, затем по 2 мин, и терпит до 8 таких шагов подряд (против 3 для негодных ответов модели);
  - отказ по `response_format` и по неизвестному полю разбирают прежние ветки — как перегрузка они не считаются.
- В панели видно, что происходит: «Сервис недоступен (503…). Жду 7 с и пробую снова — попытка 2».
- Проверено в Chromium на сервере, который отдаёт четыре 503 подряд: запуск переживает их и доходит до `done`.

- Проверено в Chromium на подставном сервере, который ведёт себя как Gemini (путь `/v1beta/openai/*`, Bearer-ключ, отказ на `stream_options`): проверка связи, пробная генерация и полный шаг агента проходят, повтор без лишних полей срабатывает.

## Доработки по реальным страницам (Яндекс Практикум)

Большая часть времени ушла на то, чтобы агент правильно видел реальный сайт. Каждая находка закреплена тестом.

| Симптом | Причина | Исправление |
|---|---|---|
| Кнопка «Пора поверстать» не подсвечивалась | Кнопки внутри кликабельной карточки считались её частью | Внутри блока с `cursor:pointer` настоящие кнопки и ссылки сохраняются |
| `Scroll: none`, хотя урок прокручивается | Прокручивается блок, а не окно | Поиск главного прокручиваемого контейнера; `scroll` крутит его |
| Десятки пустых `prisma-tooltip2__wrapper` | Обёртки-подсказки вокруг кнопок | Безымянные обёртки вокруг другого элемента убираются с перенумерацией |
| Из текста пропадали слова (`target`, `src`) | Слово-элемент вырезалось из фразы | Текст собирается абзацами, включая строчные и `inline-block` элементы |
| `"< a href = …"` в имени блока кода | Подсветка синтаксиса режет текст на `span` | Пробелы только на границах блоков |
| Модель не видела, что вариант уже выбран | `radio` с `display:none`, кликается обёртка | `label` спрятанного переключателя показывается как `input[type=radio] … checked` |
| Варианты без подписи | Кружок отдельно от текста варианта | Подпись берётся из «строки» варианта |
| Модель жала один и тот же бесполезный клик | Ни она, ни детектор не видели, что ничего не меняется | «clicked, but nothing on the page changed»; «still on the same page (URL unchanged)»; детектор сравнивает адрес, прокрутку и описание элемента |
| Блок кода принимался за кнопку перехода | Код кликабелен ради копирования | Кликабельный код (`pre`, `code`) — содержимое, а не кнопка |
| Рамки `[12]` и `[13]` вокруг всего урока и кода | `tabindex=0` на прокручиваемых областях | `tabindex` на прокручиваемом блоке — не признак клика |
| 22 пустых сегмента прогресс-бара | `tabindex` ради подсказки по фокусу | Безымянные элементы только с `tabindex` отбрасываются |
| Чекбоксы теста пропали | `input` перекрыт прозрачной иконкой-галочкой | Если переключатель скрыт или перекрыт, клик идёт по его подписи |
| Дубли «подпись + кружок» | И `label`, и `input` в списке | Подпись видимого поля не идёт отдельным элементом |
| Модель жала 👍 «Оценить» вместо проверки | Слово «Оценить» без контекста | Номера элементов прямо в тексте («Как вам задача? [21] [22]») + заметки для сайтов |
| Модель не видела редактор и «Проверить» | Тренажёр — iframe с `sandbox.practicum-team.ru` | Этап 5: iframe с других сайтов и редакторы кода |

**Заметки для сайтов** (настройки → «Заметки для сайтов»):
- шаблон адреса (домен с поддоменами, можно начало пути) и текст подсказки — он попадает в самый конец промпта;
- поле «Скрыть от модели» — тексты кнопок, которые модель не увидит и нажать не сможет (например «Оценить»).

**Как отлаживали.** Часть проверок я делал сам в вашем Chrome (Claude in Chrome): открывал урок в отдельной вкладке, только читал DOM и прогонял сборщик. На уроке ничего не нажимал.

## Отклонения от ТЗ и принятые решения

- **`reasoning` и `expected_outcome` общие для шага**, а не у каждого действия: при цепочке `actions[]` одно обоснование на цепочку экономит токены.
- **Служебные подписи в наблюдении и системный промпт на английском**: маленькие модели надёжнее следуют таким инструкциям. Ответы для вас (`done`, `ask_user`) — на языке задачи.
- **Текст страницы содержит номера элементов** (`[N]` на месте кнопки). Это расширение формата из ТЗ, сделано по согласованию.
- **Облачные API.** ТЗ их запрещало; по вашей просьбе добавлен третий профиль «Облако» (Google Gemini). «Быстрый» и «Ночной» остались локальными, и по умолчанию активен «Быстрый».
- **«Подтверждать каждый шаг»** — после этапа 6 отладочный режим, по умолчанию выключен.
- **Утренняя очередь** — не повтор действия, а новый запуск с той страницы и контекстом ночной задачи (повторить клик по старому номеру нельзя).
- **В автономном режиме рискованное сначала ждёт подтверждения N секунд со звуком**, и только потом уходит в очередь.
- **Отдельная кнопка «Сделать шаг» из этапа 3 убрана** после появления полного цикла: её заменяет пошаговый режим.
- **Content script внедряется по требованию**, а не во все страницы подряд.

## Известные ограничения и что осталось

**Ограничения:**
- Модель не видит картинок, иконок без подписей, `canvas`. Скриншоты с номерами — отдельная опция на будущее, и нужна визуальная модель (Qwen-VL, Gemma 3).
- «Почему не виден?» работает только в верхнем документе, не внутри iframe с другого сайта.
- `scroll` крутит только главную область верхней страницы.
- Утром задача из очереди начинается заново с той страницы: форму, возможно, придётся заполнять ещё раз, а платёжная сессия могла истечь.
- Классификатор риска работает по словам: «Отправить ответ» на Практикуме он посчитает отправкой. Для таких кнопок есть исключения в заметках сайта. Кнопка с иконкой без подписи («🗑») не распознаётся — помогает только флаг `risky` от модели.
- Qwen3-14B без рассуждений ошибается в смысловых решениях. Помогают заметки для сайтов, включённые рассуждения или ночной профиль 32B.

**Этап 7** — [README.md](README.md): установка, настройка llama.cpp и Ollama на сервере, файрвол, облачные провайдеры, примеры задач, разбор частых ошибок.
